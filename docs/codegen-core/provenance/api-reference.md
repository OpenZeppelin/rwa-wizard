## Generator contract

The capability is two optional members on types that already exist. `Generator<TConfig>` itself
is unchanged.

### `GenerateOptions.recordProvenance?: boolean`

Ask the generator to record which config paths each emitted file read. A generator that supports
the capability returns the recording as `GenerationResult.provenance`; a generator that does not
ignores the flag. Recording never changes generated bytes or `metadata.configHash`. Default
`false`.

### `GenerationResult.provenance?: ProvenanceResult`

Present if and only if `recordProvenance` was `true` **and** the generator supports the
capability. Absent (not `undefined`-valued — the key is not there) otherwise. Presence-test with
`hasProvenance`; do not read the field directly on an unknown generator's result.

### `hasProvenance(result: GenerationResult): result is ProvenanceGenerationResult`

Presence test for the capability on a result. `true` when `result.provenance` is a non-null object
with an own `files` object. Never throws. Does not validate individual entries — that is
`isProvenanceEntry`'s job at the point a consumer narrows untrusted data.

```ts
import { hasProvenance } from '@openzeppelin/codegen-core';
import type { GenerationResult } from '@openzeppelin/codegen-core';

export function describe(result: GenerationResult): string {
  if (!hasProvenance(result)) return 'no provenance recorded';
  return `${Object.keys(result.provenance.files).length} files recorded`;
}
```

### `type ProvenanceGenerationResult = GenerationResult & { readonly provenance: ProvenanceResult }`

The narrowed type `hasProvenance` produces.

## Result types

All result types are structural and read-only. They name a config path string, a generated-file
relative path, and a 1-indexed line range — nothing about any chain, file format, field, or
consuming application.

### `type ConfigPath = string`

A config property path in the dialect `ValidationError.field` already uses: dot-separated keys,
non-negative integer indices in brackets.

- `'settings.name'`
- `'members[1].address'`
- `'items[0].config.limit'`

The empty string is the root: the whole config was read. A path may not start with an index (the
config root is an object); an array-rooted config records the root.

### `const ROOT_CONFIG_PATH: ConfigPath = ''`

Sentinel for "the whole config". Recorded by `ownKeys` on the root view (`JSON.stringify(config)`,
`Object.keys(config)`, `{ ...config }`). Matches every query in `matchesConfigPath`, and every
recorded path matches a query of `''`.

### `interface ProvenanceLineRange { readonly start: number; readonly end: number }`

1-indexed, inclusive, `start <= end`. The same contract as the CodeView `reveal` range in
`@openzeppelin/ui-components`, so a consumer can hand a `range` entry straight to a code pane.

### `const PROVENANCE_ENTRY_KINDS: readonly ['file', 'range', 'created']`

The closed set of entry kinds, frozen. `type ProvenanceEntryKind = (typeof PROVENANCE_ENTRY_KINDS)[number]`.

### `type ProvenanceEntry`

```ts
type ProvenanceEntry =
  | { readonly kind: 'file'; readonly paths: readonly ConfigPath[] }
  | {
      readonly kind: 'range';
      readonly range: ProvenanceLineRange;
      readonly paths: readonly ConfigPath[];
      readonly secondaryPaths?: readonly ConfigPath[];
    }
  | { readonly kind: 'created'; readonly paths: readonly ConfigPath[] };
```

One attribution inside one generated file.

| Kind      | Meaning                                                                                                                                               | Per file     |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `file`    | Every config path read while producing the file's content, plus every path attached through `scope.addRange`. `paths` may be empty.                   | exactly one  |
| `created` | The paths the generator read to decide that this file exists at all (`RecordOptions.createdBy`). Disjoint from the `file` entry — not folded into it. | zero or one  |
| `range`   | The paths read to produce the lines `range` occupies in the final file (`scope.addRange`).                                                            | zero or more |

`paths` is always sorted by UTF-16 code-unit order and free of duplicates.

`secondaryPaths` is the range's **significance** mark: which of its `paths` merely display their
value rather than determine it. It is either absent or a non-empty, sorted, duplicate-free subset
of `paths` — `[]` is never recorded, because an empty secondary set is the default and one state
gets one spelling. Absence means every path is primary, and it is written only by the `addRange`
call that created the entry, so a generator that declares nothing produces the object it always
did. `file` and `created` entries never carry it. Read it through
[`isSecondaryAttribution`](#issecondaryattributionentry-provenanceentry-query-configpath-boolean),
never directly: a query is a prefix query while a mark is per exact path. See
[significance.md](./significance.md).

### `interface FileProvenance { readonly entries: readonly ProvenanceEntry[] }`

Entries for one generated file, in canonical order: the `file` entry, then the `created` entry if
any, then `range` entries sorted by `start` then `end`.

### `interface ProvenanceResult { readonly files: Readonly<Record<string, FileProvenance>> }`

Provenance for one generation. Keys are the same relative paths as `GenerationResult.files`, in
first-recorded order. A key present in `GenerationResult.files` but absent here means the
generator emitted that file outside any recording scope — a migration gap, not "depends on
nothing". A file that depends on nothing has a `file` entry with `paths: []`.

### `interface Observed<R> { readonly value: R; readonly paths: readonly ConfigPath[] }`

A value computed under recording, together with what it read. Returned by
`ProvenanceCollector.observe`.

## Collector

The collector is what a generator holds for one `generate()` call. It opens one recorder per
scope, closes it when the scope ends, and assembles the result.

### `createProvenanceCollector<T extends object>(config: T, options?: ProvenanceCollectorOptions): ProvenanceCollector<T>`

One collector per `generate()` call. Pass `{ enabled: options?.recordProvenance === true }`. No
state is shared between collectors; two collectors over equal configs given the same sequence of
reads produce deep-equal results.

### `interface ProvenanceCollectorOptions { readonly enabled?: boolean }`

Mirrors `GenerateOptions.recordProvenance`. Default `false`. When disabled, every method runs the
same control flow with the raw config and records nothing — `result()` returns `undefined`,
`scope.drain()` returns `[]`, `observe(...).paths` is `[]`, and `scope.config === config`.

### `interface ProvenanceCollector<T extends object>`

```ts
interface ProvenanceCollector<T extends object> {
  readonly enabled: boolean;
  record<R>(
    filePath: string,
    produce: (scope: ProvenanceScope<T>) => R,
    options?: RecordOptions
  ): R;
  createFile(
    filePath: string,
    produce: (scope: ProvenanceScope<T>) => string | Uint8Array,
    options?: RecordOptions
  ): FileTree;
  observe<R>(compute: (config: T) => R): Observed<R>;
  result(): ProvenanceResult | undefined;
}
```

#### `enabled: boolean`

`true` iff `options.enabled` was `true`. Branch on it only to skip attribution work that is
expensive; never to change what files are produced.

#### `record<R>(filePath, produce, options?): R`

Produce one file under its own recording scope and return whatever `produce` returns.

- Everything `produce` reads through `scope.config` becomes the file's `file` entry.
- Ranges added through `scope.addRange` become `range` entries; their paths are folded into the
  `file` entry too.
- `options.createdBy`, if given, becomes the file's `created` entry.
- Recording the same `filePath` again **replaces** its previous entries wholesale and keeps its
  original position in `result().files`.
- Scopes do not nest: calling `record` or `createFile` while another `produce` is running throws
  `ProvenanceScopeError('nested', innerFilePath)` before running the inner `produce`. The outer
  scope is unaffected. This is checked whether or not recording is enabled.
- `produce` is synchronous: the scope closes when it returns. A `produce` that returns a `Promise`
  gets that `Promise` back unchanged, but every view read after the return throws
  `ProvenanceScopeError('closed', filePath)`.
- A `produce` that throws propagates its error unchanged; the scope closes; the file is not
  recorded; the collector stays usable.
- If `produce` returns a view or a plain container holding views, `record` returns the
  deep-unwrapped value (`unwrapDeep`): each view becomes its raw target; non-plain objects are
  left alone. When disabled: runs `produce` with `scope.config` set to the raw config and records
  nothing.

**Throws:** `ProvenanceScopeError('nested')` on nesting; `ProvenanceScopeError('closed')` after
`result()` was called.

#### `createFile(filePath, produce, options?): FileTree`

`record` specialised to one text or binary file: returns `createFile(filePath, content)` from the
file-tree utilities, so the recorded key and the tree key are one literal. Merge the returned tree
with `mergeFileTrees`. Same scope rules and errors as `record`.

```ts
const tree = collector.createFile('README.md', ({ config: c }) => `# ${c.settings.name}\n`);
// tree is { 'README.md': '# …\n' } and provenance.files['README.md'] has paths ['settings.name']
```

#### `observe<R>(compute): Observed<R>`

Run a computation under recording **without attaching it to a file** and get back both the value
and the paths it read. Use it for decisions made outside any template — which modules are enabled,
which workspace members exist — and pass the paths as `createdBy` to the files that decision
governs. Allowed anywhere, including inside a `record` scope; its reads attribute to no file.

`value` is deep-unwrapped (`unwrapDeep`): if `compute` returns a view or a plain container holding
views, each view becomes its raw target. Non-plain objects are left alone. Prefer returning
primitives, ids, or fresh objects when you do not need that walk.

When disabled, `paths` is `[]` and `compute` receives the raw config.

**Throws:** `ProvenanceScopeError('closed')` after `result()` was called.

```ts
const enabled = collector.observe((c) => c.modules.map((m) => m.id)); // value: string[]
for (const id of enabled.value) {
  files = mergeFileTrees(
    files,
    collector.createFile(`modules/${id}.txt`, ({ config: c }) => render(c, id), {
      createdBy: enabled.paths, // ['modules', 'modules[0].id', …]
    })
  );
}
```

#### `result(): ProvenanceResult | undefined`

The assembled result, or `undefined` when disabled. Idempotent — repeated calls return the same
object — and **closes the collector**: any later `record`, `createFile` or `observe` throws
`ProvenanceScopeError('closed')`. Entries per file are in canonical order; `paths` sorted and
deduplicated; files keyed in first-recorded order.

### `interface ProvenanceScope<T extends object>`

```ts
interface ProvenanceScope<T extends object> {
  readonly filePath: string;
  readonly config: T;
  drain(): ConfigPath[];
  addRange(range: ProvenanceLineRange, paths: readonly ConfigPath[]): void;
}
```

The handle `produce` receives. It carries a recording view into the template and nothing else, so
a helper handed a scope can only ever attribute to the file being produced.

#### `filePath: string`

The relative path of the file this scope records — the `record`/`createFile` argument, verbatim.
Lets a helper that receives only a scope name the file it is producing (a range builder, a
diagnostic, a test) without threading the literal through a second parameter.

#### `config: T`

The recording view of the config for this file, typed as `T` so existing template signatures
(`(config: T) => string`) accept it unchanged. The raw config when the collector is disabled.

#### `drain(): ConfigPath[]`

The paths read through this scope since the previous `drain()` (or since the scope opened),
sorted, deduplicated and pruned (see [Recording rules](#recording-rules)). Resets the cursor; the file's `file` entry still includes them. This is
the primitive for line-level attribution: emit a line, `drain()`, `addRange` the drained paths to
the line's range. `[]` when disabled.

**Throws:** `ProvenanceScopeError('closed', filePath)` after `produce` has returned.

#### `addRange(range, paths, options?): void`

Attach a `range` entry to this file. `paths` is normalised (sorted, deduplicated) and folded into
the file's `file` entry. The range's **shape** is validated even when disabled — `start` and `end`
must be integers with `1 <= start <= end` — but its position against the final text is the
caller's responsibility; the scope cannot know the text length while `produce` is still running.

`options.secondaryPaths` is normalised the same way and recorded as the entry's `secondaryPaths`,
omitted entirely when empty. This is the **only** writer of significance in the package: an entry
carries a mark if and only if the call that created it named one. The entry's mark never reaches
the file's `file` entry.

The call is total. Every guard runs before any state is written, so a rejected `addRange` records
nothing and leaves the scope usable.

**Throws:** `RangeError` on an invalid shape (always);
`ProvenanceAttributionError('secondary-not-attributed', filePath, offending)` when
`options.secondaryPaths` names a path this range does not attribute (always, regardless of
`enabled`); `ProvenanceScopeError('closed', filePath)` after `produce` has returned.

### `interface AddRangeOptions { readonly secondaryPaths?: readonly ConfigPath[] }`

Which of `addRange`'s `paths` merely display their value rather than determine it. Must be a subset
of `paths`; a path the range does not attribute is a template bug and throws. `[]` and `undefined`
are equivalent — both record nothing.

This is the general, per-attribution primitive: it accepts an arbitrary subset, so significance may
differ between the paths of one range. Templates usually reach for the ergonomic per-emission form
instead — see [`EmitOptions`](#interface-emitoptions).

### `interface RecordOptions { readonly createdBy?: readonly ConfigPath[] }`

Paths the generator read to decide this file exists; becomes the file's `created` entry,
normalised. Usually `collector.observe(...).paths`.

## Recorder

The recorder is the layer under the collector. Generators normally never touch it; it is exported
for tests, for building higher-level attribution tools, and for anyone who needs a recording view
outside the per-file model.

### `createConfigRecorder<T extends object>(config: T): ConfigRecorder<T>`

Wrap `config` in a recording view. Pure: two recorders over equal configs given equal access
sequences produce equal paths; no state is shared between recorders. The recorder has no
`close()` — it records for as long as it is reachable. (The collector's scopes close their views;
a bare recorder's do not.)

### `interface ConfigRecorder<T extends object>`

```ts
interface ConfigRecorder<T extends object> {
  readonly view: T;
  drain(): ConfigPath[];
  all(): ConfigPath[];
}
```

- `view` — the recording view, typed as `T`. Every property access through it is logged. Reads
  return the original values for primitives, functions and non-plain objects, or a cached child
  view for plain objects and arrays (`view.a === view.a`). Writes, deletes and `defineProperty`
  throw `ProvenanceViewMutationError`.
- `drain()` — paths read since the previous `drain()` (or since creation), sorted, deduplicated
  and pruned within that window: a traversal whose descendant was also read in the window is
  dropped; terminal reads are kept. Resets the cursor.
- `all()` — every path read since creation regardless of drains, sorted, deduplicated and pruned
  over the whole history — so a traversal reported by an early `drain()` is collapsed here once
  its leaf was read in a later window.

### `const CONFIG_RECORDER_PROBE_KEYS: ReadonlySet<string>`

Exactly `{ 'toJSON', 'then' }`: keys the JavaScript runtime probes on its own (`JSON.stringify`
looks for `toJSON`; `await` and `Promise.resolve` look for `then`) that are never a config read.
Fixed and frozen; not extensible, because an extension point would be a place for one generator
to hide a real read.

### Recording rules

Recording is shape-driven and value-independent. Each access is classified at the trap: a `get`
that returns a child view (the value is a plain object or array) is a **traversal**; every other
recording access — a `get` returning a primitive, `undefined` or a raw non-plain object, `has`,
`getOwnPropertyDescriptor`, `ownKeys`, and on arrays `length`, method keys and `has` — is
**terminal**. When `drain()` or `all()` reports a set, a traversal path is dropped if the same set
holds a strict segment-boundary descendant of it; a terminal path is never dropped. The rows below
give the **reported** set for each access.

| Access through the view                                                                                           | Records                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `v.settings.name` — any value, including `''`, `false`, `0`, `null`, `undefined`, absent key                      | `settings.name` — the `settings` traversal is pruned                                                                                                                                                   |
| `v.settings?.missing?.deeper`                                                                                     | `settings.missing` — nothing deeper, because output cannot depend on a member of nothing                                                                                                               |
| `'x' in v.settings`, `Object.hasOwn(v.settings, 'x')`                                                             | `settings.x`                                                                                                                                                                                           |
| `Object.keys(v.settings)`, `{ ...v.settings }`, `JSON.stringify(v.settings)`                                      | `settings` (terminal, kept) plus `settings.<key>` for each own key enumerated; `JSON.stringify` also every nested object path and leaf                                                                 |
| `JSON.stringify(v)`, `Object.keys(v)`                                                                             | `''` (the root, always kept) plus each top-level key and, for `JSON.stringify`, everything beneath                                                                                                     |
| `v.members[1].address`                                                                                            | `members[1].address` — `members` and `members[1]` are traversals and pruned                                                                                                                            |
| `v.members.length`, `for (const m of v.members)`, `.map`, `.filter`, `[...v.members]`, `Array.isArray(v.members)` | `members` (terminal: `length`, method keys and `has` read the array itself) plus `members[i].<leaf>` for each element leaf read; a bare `members[i]` is kept only when the element was read as a whole |
| `if (v.settings)`, `Array.isArray(v.members)`, `const s = v.settings` with no further read                        | `settings` / `members` — a traversal with no recorded descendant is kept                                                                                                                               |
| `v.settings.name` then `if (v.settings)` in one scope                                                             | `settings.name` — a truthiness test is itself a traversal (a `get` returning a child view), so it is pruned once a descendant was read                                                                 |
| `Reflect.ownKeys(v.settings)`                                                                                     | `settings` only                                                                                                                                                                                        |
| `Object.keys(v.members)`                                                                                          | `members` plus `members[i]` for every index                                                                                                                                                            |
| `v.members['01']`, `v.members['-1']` (non-canonical index strings)                                                | `members` — the array path, not an element                                                                                                                                                             |
| `v.settings.toJSON`, `v.then`                                                                                     | nothing (probe keys)                                                                                                                                                                                   |
| `v.settings.constructor`, `.toString`, `.valueOf`, `.__proto__`                                                   | nothing (inherited, not own)                                                                                                                                                                           |
| `v[Symbol.iterator]`, any symbol key                                                                              | nothing                                                                                                                                                                                                |
| `v.settings['weird.key']`, `v.settings['']`                                                                       | `settings` — the parent path; the raw value is returned. Keys containing `.`, `[` or `]` cannot be carried by the dialect                                                                              |
| `v.settings['名前']`                                                                                              | `settings.名前` — non-ASCII keys are carried verbatim                                                                                                                                                  |
| `v.createdAt.toISOString()` where `createdAt` is a `Date`                                                         | `createdAt` — the `Date` is returned raw; descent stops at non-plain objects (`Date`, `Map`, `Set`, typed arrays, class instances, functions)                                                          |
| `v.settings.name = 'x'`, `delete v.settings.name`, `Object.freeze(v.settings)`                                    | throws `ProvenanceViewMutationError` naming `settings.name` (or `settings`) and the operation                                                                                                          |
| `structuredClone(v)`                                                                                              | throws `DataCloneError` (host behaviour — a `Proxy` cannot be cloned)                                                                                                                                  |

Other guarantees:

- `JSON.stringify(view) === JSON.stringify(config)`, and `computeConfigHash(view) ===
computeConfigHash(config)` — but do not hash the view in a generator; that attributes every field
  to the current file.
- `Array.isArray(view.members)` is `true`; `Object.getPrototypeOf(view.x)` matches the real
  object; `Object.isFrozen(view)` is `false` even when `config` is frozen.
- Frozen (deep-frozen, immer-produced) and null-prototype configs record identically and never
  trip a `Proxy` invariant error.
- One view per distinct object per recorder: repeated reads of the same sub-object return the same
  view and allocate nothing.
- A read on an array-rooted config records the root `''` for element access, because a path may
  not start with an index.
- Pruning happens only at the recorder's report seam (`drain()`, `all()`), so `ProvenanceScope.drain`,
  `observe().paths` and the file entry inherit it. `addRange`, `mergeProvenance` and
  `filterProvenanceByPath` never prune what they are given.

## Line attribution

Two builders that turn a scope into a stream of attributed emissions, so a generated file records
which config paths produced which lines. Both are bound to exactly one `ProvenanceScope`, both
seal at `text()`, and both are byte-transparent: the text they return is what the equivalent
un-instrumented code would have produced.

See [line-attribution.md](./line-attribution.md) for the rule these enforce — a config read must
happen at the emit site, not before it — and for the ESLint guard that catches the cases no
runtime check can see.

### `createLineBuilder<T extends object>(scope: ProvenanceScope<T>, options?: LineBuilderOptions): LineBuilder<T>`

```ts
function createLineBuilder<T extends object>(
  scope: ProvenanceScope<T>,
  options?: LineBuilderOptions
): LineBuilder<T>;
```

The push-and-join emission idiom with line attribution. Must be the **first** thing that touches
its scope: the constructor drains the scope and throws
`ProvenanceAttributionError('reads-before-builder')` if anything was read before, naming the
paths and the file. Throws `ProvenanceAttributionError('builder-exists')` if the scope already has
a builder of either kind. Both guards fire whether or not recording is enabled.

### `interface LineBuilderOptions { readonly separator?: string }`

`separator` is joined between elements exactly as `Array.prototype.join`. Default `'\n'`. It is
never inferred — a template that joined with anything else must pass it, or the output changes.

### `interface LineSink`

```ts
interface LineSink {
  line(text: string, extraPaths?: readonly ConfigPath[], options?: EmitOptions): void;
  lines(texts: readonly string[], extraPaths?: readonly ConfigPath[], options?: EmitOptions): void;
  block(text: string, extraPaths?: readonly ConfigPath[], options?: EmitOptions): void;
}
```

The emission surface a helper accepts without knowing the config type — no `config`, no `observe`,
no `text`. Every method attributes what it emits to the paths read since the previous emission,
plus paths left pending by zero-line emissions and `observe`, plus `extraPaths`; a `range` entry
is recorded only when that union is non-empty. `extraPaths` is a **union** with the drained paths,
never a replacement.

Methods return `void`: an emission is a statement, never an expression.

#### `line(text, extraPaths?, options?): void`

One element. `text` may contain `'\n'`, in which case it occupies several lines and the recorded
range covers them.

#### `lines(texts, extraPaths?, options?): void`

Several elements, attributed as **one** range covering all of them — not one range per element.
An empty array emits nothing and leaves the pending paths for the next emission that produces
bytes.

#### `block(text, extraPaths?, options?): void`

Identical to `line`. A separate name for the call site where the text is expected to span several
lines; there is no behavioural difference.

### `interface EmitOptions`

```ts
interface EmitOptions {
  readonly secondary?: boolean;
}
```

`secondary: true` marks **every** path this emission attributes as secondary — the paths drained
since the previous emission, the pending window, and `extraPaths` — by forwarding them as
`AddRangeOptions.secondaryPaths` to the same `addRange` that records the range. Only the literal
`true` marks; nothing else is truthy here.

The mark applies to **this call only**. It is never pending and never drained, so a zero-line
emission (`lines([])`) discards it while still carrying its paths forward — a zero-line emission
has no range, so it has nothing to be secondary about. An emission whose path union is empty
records no entry at all, mark included.

Because the range, the path union and the mark are three values in one call frame consumed by one
`addRange`, the site marked is the site emitted. See [significance.md](./significance.md).

### `interface LineBuilder<T extends object> extends LineSink`

```ts
interface LineBuilder<T extends object> extends LineSink {
  readonly config: T;
  observe<R>(compute: (config: T) => R): Observed<R>;
  readonly lineCount: number;
  text(): string;
}
```

#### `config: T`

The scope's recording view of the config — the only handle a template needs. Reads through it are
attributed to the next emission.

#### `observe<R>(compute): Observed<R>`

Compute a value used across emissions and get its paths back **without** attributing them here.
Pass `.paths` to every emission the value shapes. Reads made since the previous emission stay
pending rather than being attributed to the `observe`. Throws `emit-after-text` once sealed.

#### `lineCount: number`

The number of lines `text()` would have now; `0` before the first emission.

#### `text(): string`

`elements.join(separator)`. Idempotent and memoised, and it **seals** the builder: a later
emission would describe lines the returned text does not have, so it throws
`ProvenanceAttributionError('emit-after-text')`. Paths still pending at `text()` attribute to no
range — they shaped no bytes — but remain in the file's `file` entry.

### `createPatchBuilder<T extends object>(scope: ProvenanceScope<T>, source: string): PatchBuilder<T>`

```ts
function createPatchBuilder<T extends object>(
  scope: ProvenanceScope<T>,
  source: string
): PatchBuilder<T>;
```

Line attribution over the exact source-patch primitives, for files produced by patching upstream
text. Same construction rules as `createLineBuilder`: first toucher of the scope, one builder per
scope.

### `interface PatchSink`

```ts
interface PatchSink {
  replaceExact(search: string, replacement: string, extraPaths?: readonly ConfigPath[]): void;
  insertBeforeExact(marker: string, insertion: string, extraPaths?: readonly ConfigPath[]): void;
  insertAfterExact(marker: string, insertion: string, extraPaths?: readonly ConfigPath[]): void;
}
```

The core `replaceExact` / `insertBeforeExact` / `insertAfterExact` primitives one-for-one, plus
attribution, with the same path union rule as `LineSink`. Each rewrites the **first** occurrence, and each throws before any
builder state moves when the search string is absent — so a failed edit leaves the builder exactly
as it was.

- `replaceExact` attributes the replaced region **even when the bytes are unchanged**. Call it
  unconditionally rather than returning early on "already matches upstream", or the dependency is
  lost.
- `insertBeforeExact` / `insertAfterExact` attribute only the **inserted** bytes; the marker is
  excluded whenever the written piece carries it verbatim.

### `interface PatchBuilder<T extends object> extends PatchSink`

```ts
interface PatchBuilder<T extends object> extends PatchSink {
  readonly config: T;
  observe<R>(compute: (config: T) => R): Observed<R>;
  readonly current: string;
  text(): string;
}
```

#### `current: string`

The text after every edit so far, as a plain string. Reading it records nothing.

#### `text(): string`

The final text — byte-identical to applying the same edits with `replaceExact`,
`insertBeforeExact` and `insertAfterExact` directly, replacement-pattern semantics included.
Resolves every tracked region to a line range **against this final text**, in insertion order, and
records the ones carrying paths. Idempotent; seals the builder. Lines that came from `source` and
were never edited are attributed to nothing.

Each edit is tracked as a byte region of the _current_ text and shifted by every later edit, so an
edit near the top does not invalidate regions recorded below it. Where a later edit lands inside
an earlier region, the surviving parts keep their paths and the overlapping part's paths join the
new region.

## Path algebra

The dialect is parsed and formatted in one place so that a generator, a consumer, and a test all
agree on what `members[1].address` means.

### `type ConfigPathSegment`

```ts
type ConfigPathSegment =
  | { readonly kind: 'key'; readonly key: string }
  | { readonly kind: 'index'; readonly index: number };
```

One step of a path. Keys are emitted verbatim; indices are non-negative integers.

### `parseConfigPath(path: ConfigPath): ConfigPathSegment[]`

`''` → `[]`; `'a.b[2].c'` → `[key a, key b, index 2, key c]`.

**Throws** `RangeError` on malformed input: empty key segments (`'a..b'`, `'.a'`, `'a.'`), a
leading index (`'[0]'`), a non-canonical index (`'a[01]'`, `'a[-1]'`, `'a[x]'`, `'a[ 1]'`), an
unterminated bracket (`'a['`), or a stray `]`. The message names the path and the offset, never a
config value.

### `formatConfigPath(segments: readonly ConfigPathSegment[]): ConfigPath`

Inverse of `parseConfigPath`; `formatConfigPath(parseConfigPath(p)) === p` for every path the
recorder can emit.

**Throws** `RangeError` for a segment list the dialect cannot carry: a leading index, a key that
is empty or contains `.`, `[` or `]`, or a non-integer or negative index.

### `matchesConfigPath(recorded: ConfigPath, query: ConfigPath): boolean`

The one matching rule. `true` when `recorded` and `query` are equal or one is a segment-boundary
prefix of the other. Symmetric.

| `recorded`           | `query`              | Result  | Why                                        |
| -------------------- | -------------------- | ------- | ------------------------------------------ |
| `settings`           | `settings.name`      | `true`  | parent read, child asked                   |
| `items[0].id`        | `items[0]`           | `true`  | child read, parent asked                   |
| `''`                 | anything             | `true`  | the root matches every query               |
| anything             | `''`                 | `true`  | every recorded path matches the root query |
| `members[1].address` | `members[0].address` | `false` | sibling elements                           |
| `settings.nameX`     | `settings.name`      | `false` | segment comparison, never string prefix    |
| `a[1]`               | `a.1`                | `false` | segment kinds must agree                   |

**Throws** `RangeError` on a malformed argument rather than returning `false`. A malformed query
is a bug in the caller and should fail loudly in its tests.

### `omitExactConfigPath(paths: readonly ConfigPath[], path: ConfigPath): readonly ConfigPath[]`

Emit-path hygiene for list-scan attribution (hazard 5). Drops every occurrence of `path` from
`paths` by **exact string equality** only — never parses, never calls `matchesConfigPath`, never
mutates `paths`.

| Behaviour | Detail |
| --------- | ------ |
| Exact only | `'members'` does not remove `'members[0].addresses'` |
| Absent path | Returns `paths` by reference (identity no-op) |
| At least one removed | Fresh array; relative order of survivors preserved |

Use after a list walk that only needed a match: omit the list root before the path list reaches an
emit. Do not omit when the emit depends on the whole list (iteration, join, length). See
[attribution-hazards.md](./attribution-hazards.md) hazard 5 and the README's list-scan note.

## Result helpers

Pure functions over `ProvenanceResult`. None mutates its input; each returns a fresh object.

### `isProvenanceEntry(value: unknown): value is ProvenanceEntry`

Structural guard for one entry: a non-array object whose `kind` is one of
`PROVENANCE_ENTRY_KINDS`, whose `paths` is an array of strings, and — for `range` — whose `range`
has integer `start >= 1` and `end >= start`. Returns `false` for anything else, including objects
whose getters throw. **Never throws.** This is the one function designed to be fed untrusted
shapes; use it where provenance crosses a trust boundary (deserialised JSON, a generator you do
not control).

### `mergeProvenance(...results: readonly ProvenanceResult[]): ProvenanceResult`

Combine results the way `mergeFileTrees` combines trees: later arguments win per file key,
**wholesale** — a re-emitted file's earlier entries describe text that no longer exists, so they
are replaced, never merged. Keys only in earlier results are kept. Key order is the first result's
keys followed by each later result's new keys. Use it wherever you already `mergeFileTrees` the
output of two generate paths.

```ts
import { hasProvenance, mergeProvenance } from '@openzeppelin/codegen-core';
import type { GenerationResult, ProvenanceResult } from '@openzeppelin/codegen-core';

function withOverrides(
  base: GenerationResult,
  overrides: ProvenanceResult | undefined
): GenerationResult {
  if (!hasProvenance(base) || overrides === undefined) return base;
  return { ...base, provenance: mergeProvenance(base.provenance, overrides) };
}
```

### `filterProvenanceByPath(result: ProvenanceResult, query: ConfigPath): ProvenanceResult`

The entries relevant to one queried config path, per file, using `matchesConfigPath`. Files with
no matching entry are omitted; a matching file keeps only its matching entries, each returned by
identity and in input order — entries are not narrowed or rewritten. An entry with empty `paths`
matches no query, including the root. An empty `files` means "no generated file depends on this
path", which is an answer, not an error. A file whose scope read only `settings.name` is **not**
returned for `settings.symbol` (the `settings` traversal was pruned at report time); a file whose
scope read `settings` as an object (`Object.keys`, `JSON.stringify`, or `if (c.settings)` with
nothing read beneath) is
returned for every `settings.*` query, present or absent.

**Throws** `RangeError` on a malformed `query` or a malformed recorded path.

```ts
const hits = filterProvenanceByPath(result.provenance, 'members[1].address');
for (const [filePath, { entries }] of Object.entries(hits.files)) {
  for (const entry of entries) {
    if (entry.kind === 'range') console.log(filePath, entry.range.start, entry.range.end);
    else console.log(filePath, entry.kind);
  }
}
```

### `isSecondaryAttribution(entry: ProvenanceEntry, query: ConfigPath): boolean`

Is this entry's attribution to `query` **secondary** — displayed rather than determined?

`true` only when the entry is a marked `range`, **and** it matches `query`, **and every** matching
path is in `secondaryPaths`. Matching is `matchesConfigPath`'s rule, so a prefix query answers over
every recorded path beneath it and a recorded ancestor answers a descendant query.

Returns `false` for a `file` or `created` entry, an unmarked `range`, an entry that matches nothing,
and an entry with any primary matching path. The match-nothing case is guarded explicitly rather
than left to `Array.prototype.every`, which is vacuously `true` over an empty list.

**Throws** `RangeError` on a malformed `query` or a malformed recorded path, like
`filterProvenanceByPath`. The query is parsed before the entry kind is narrowed, so a bad query
throws for every kind.

```ts
const entry = {
  kind: 'range',
  range: { start: 12, end: 12 },
  paths: ['token.name', 'token.symbol'],
  secondaryPaths: ['token.symbol'],
} as const;

isSecondaryAttribution(entry, 'token.symbol'); // true
isSecondaryAttribution(entry, 'token.name'); // false
isSecondaryAttribution(entry, 'token'); // false — `token.name` is primary
isSecondaryAttribution(entry, 'settings'); // false — matches nothing
```

Use it rather than reading `secondaryPaths`. Both inline shortcuts are wrong in opposite
directions: `secondaryPaths.length > 0` demotes a range that determines a sibling path, and
`secondaryPaths.includes(query)` promotes everything a prefix query reaches. See
[significance.md § Reading significance](./significance.md#reading-significance-issecondaryattribution).

## Errors

Every failure inside the capability is a programming error in a generator, not a runtime
condition a consumer should branch on, so the module throws typed errors and returns no `Result`
type. Nothing is logged. Messages name paths and operations, never config values.

### `class ProvenanceViewMutationError extends Error`

```ts
class ProvenanceViewMutationError extends Error {
  readonly code: 'PROVENANCE_VIEW_MUTATION';
  readonly path: ConfigPath;
  readonly operation: ProvenanceViewMutation;
  constructor(path: ConfigPath, operation: ProvenanceViewMutation);
}
type ProvenanceViewMutation = 'set' | 'delete' | 'define' | 'setPrototype' | 'preventExtensions';
```

Thrown by every mutating trap on a recording view. `path` is the path of the operation's target,
formatted the way a read would record it; `operation` is the trap. `name` is
`'ProvenanceViewMutationError'`. The config is untouched.

### `class ProvenanceScopeError extends Error`

```ts
class ProvenanceScopeError extends Error {
  readonly code: 'PROVENANCE_SCOPE';
  readonly reason: ProvenanceScopeErrorReason;
  readonly filePath?: string;
  constructor(reason: ProvenanceScopeErrorReason, filePath?: string);
}
type ProvenanceScopeErrorReason = 'nested' | 'closed';
```

Thrown on scope-structure misuse, whether or not recording is enabled:

- `'nested'` — `record` or `createFile` was called while another scope's `produce` was running.
  `filePath` is the **inner** file.
- `'closed'` — a collector was used after `result()`, or a scope's view, `drain` or `addRange`
  was used after its `produce` returned. `filePath` is the scope's file when there is one.

`name` is `'ProvenanceScopeError'`.

### `class ProvenanceAttributionError extends Error`

```ts
class ProvenanceAttributionError extends Error {
  readonly code: 'PROVENANCE_ATTRIBUTION';
  readonly reason: ProvenanceAttributionErrorReason;
  readonly filePath: string;
  readonly paths: readonly ConfigPath[];
  constructor(
    reason: ProvenanceAttributionErrorReason,
    filePath: string,
    paths?: readonly ConfigPath[]
  );
}
type ProvenanceAttributionErrorReason =
  | 'reads-before-builder'
  | 'builder-exists'
  | 'emit-after-text'
  | 'secondary-not-attributed';
```

Thrown when a builder or a scope cannot attribute honestly. Every reason fires whether or not
recording is enabled, so the mistake surfaces in tests that never turn it on. `filePath` is always
the file being produced; `paths` is populated for `'reads-before-builder'` and
`'secondary-not-attributed'`, and is `[]` otherwise.
`name` is `'ProvenanceAttributionError'`.

- `'reads-before-builder'` — config was read through the scope before its builder was created.
  Those reads would silently land on whatever the builder emits first. `paths` names them.
- `'builder-exists'` — a second builder was bound to a scope that already has one. Two builders
  would split the drain and misattribute silently.
- `'emit-after-text'` — an emission, patch, or `observe` after `text()` sealed the builder.
- `'secondary-not-attributed'` — `addRange` was given `secondaryPaths` naming a path the range does
  not attribute. `paths` names the offending ones. Thrown by the scope rather than by a builder,
  before any state is written, so the scope stays usable.

Messages name the file, the reason, and for the first case the offending paths — never a config
value and never emitted text.

### `RangeError` (built-in)

Thrown by `parseConfigPath`, `formatConfigPath`, `matchesConfigPath`, `filterProvenanceByPath`
on malformed paths, and by `ProvenanceScope.addRange` on an invalid range shape.
